# Security
Normal app operation does not require elevation. No arbitrary shell evaluation or remote API execution is present. SQL values are parameterized. Clipboard monitoring requires session consent and content is memory-only. Configuration contains no intended secrets and is not encrypted.

Outputs use collision-safe/create-new writes where possible; explicitly chosen Save dialogs may confirm replacement. ZIP extraction validates normalized paths, rejects rooted/colon/backslash paths and symbolic-link entries, writes to an isolated new directory, and caps expansion at 2 GB / 5000 entries. It does not claim sandboxing against every local filesystem race. Workflow input/output roots must be disjoint; file access is checked against approved roots and linked folders/files are rejected. The runner never evaluates imported commands. Rename rollback is best-effort and surfaces failures.

Resource limits reduce accidental overload but are not a security boundary for malicious codec/PDF inputs. Full fuzzing, performance profiling, package signing, and a complete dependency/license/security audit remain required before release. Report vulnerabilities privately to the repository owner; establish a real published security contact before distribution. Never commit signing credentials.
